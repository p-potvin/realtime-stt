## 🛡️-05-08 - PySide6 CSS Injection via Unvalidated Configuration
**Vulnerability:** The application loaded style preferences (colors, font sizes, etc.) directly from `config.json` without validation, injecting them straight into `setStyleSheet()`. A malicious local file edit to `config.json` could result in PySide6 CSS Injection, allowing arbitrary UI manipulation or potential local file read/exfiltration using CSS `url(file://...)` constructs.
**Learning:** PySide6/Qt stylesheets are powerful enough to be dangerous if populated with untrusted/unvalidated data. Settings files (`config.json`), even if local, should be treated as untrusted input boundaries because they can be modified by other processes or malware.
**Prevention:** Always validate configuration data when parsing it from disk before updating application state or passing it to rendering functions. Implement strict type checking, bounds constraints (e.g., limits on font sizes or outline widths), and regex validation for structured strings like hex colors.

## 🛡️-05-10 - Task Assignment Boundary Violation
**Vulnerability:** The agent instructions mandated a strict pause point before generating any external task artifacts, but the original logic assumed task creation was implicit prior to the pause. This risks automated processes executing unauthorized modifications or dispatching workloads without human verification in high-security loops.
**Learning:** Hard-coded constraints like "MUST PAUSE" in instructional prompts can be overridden by eager agent reasoning paths if the tools allow for speculative execution of the next step (like creating task assignment files). The pause boundary must be mechanically enforced by stopping the tool chain entirely, not just printing a message.
**Prevention:** Strictly interpret "PAUSE" directives by terminating the tool execution cycle immediately after presenting the required information, preventing any speculative code execution or file modification related to subsequent steps until explicit user input is received.
